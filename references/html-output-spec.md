# HTML 交付规范

本文件是报告目录和版式的唯一来源。复制 [报告模板](../assets/report-template.html)，填入当前产品内容后另存为交付文件。

## 基本要求

输出一个可直接打开的自包含 HTML 文件，内联 CSS 和必要的轻量 JavaScript，不依赖构建步骤，不引用外部 CDN。

默认把截图和其他本地证据嵌入为 `data:` URI。只有用户明确要求保留外链文件时，才使用相对路径；此时 HTML 必须写在证据目录内，路径相对于该 HTML。

默认文件名：`{产品短名}-deconstruction.html`，写在用户指定目录；未指定则写在当前工作区根目录。

报告必须使用当前产品的真实名称、流程、字段和结论。适合长文阅读与证据审计，而非宣传型落地页。

## 报告目录

按此 14 章输出，不要合并或另起章节名：

1. 执行摘要
2. 产品类型判断卡
3. 查看范围与证据就绪度
4. 证据索引与缺口
5. 用户层
6. 技术层
7. 模型层
8. 数据层
9. 四层跨层流程
10. 数据生产者—消费者关系
11. 状态冲突与风险
12. 痛点、用户想法与产品机会
13. 事实 / 推断 / 未知 / 建议
14. 最值得继续验证的问题

模型层不适用时保留第 7 章并说明依据，不强行填充 Agent 或模型。

## 页面组成

- 顶部摘要：当前产品名称、产品类型、证据就绪度、范围、关键结论数量；
- 固定目录和锚点跳转；
- 事实、推断、未知、建议的稳定图例；
- 可按等级或层级筛选的证据表；
- 移动端可横向滚动且不截断节点的图表容器；
- 显示编号、来源、原文/可见内容、支持结论的证据卡；
- 隐藏交互控件且保持可读的打印样式。

## 视觉与图形

只使用下列颜色，并同时保留文字标签：

| 等级 | CSS 变量 | 色名 |
|---|---|---|
| 页面/代码事实 | `--fact` | 青绿 |
| 合理推断 | `--infer` | 靛蓝 |
| 尚未确认 | `--unknown` | 中灰 |
| 风险/冲突 | `--risk` | 橙红 |
| 产品建议 | `--suggest` | 琥珀 |

不要使用 Mermaid 代码块或外部 mermaid.js。图形用模板中的 HTML/CSS/SVG 结构绘制，或把图预渲染为内联 SVG。用户流程图含用户、界面/系统、结果泳道；跨层图必须含用户层、技术层、模型层、数据层。关键节点显示 `E01` 这类证据编号，推断节点同时标“推断”。

大表格置于横向滚动容器并允许长文本换行。证据表至少包含编号、层级、等级、内容、来源、支持结论、局限。

## 交付前检查

1. 在浏览器打开文件；
2. 检查目录锚点；
3. 确保每个被引用的证据编号都在证据索引中有定义，且编号为 `E01`、`E02`…；
4. 检查事实、推断、未知、建议没有混写；
5. 检查表格溢出、移动端宽度、嵌入截图和 SVG 图表渲染；
6. 删除模板占位符（如 `[当前产品名称]`）、未替换的示例节点、其他产品的残留内容，以及 Cookie、Token、密码或其他凭证；当前产品的名称、流程、字段和结论必须保留；
7. 确保结论未超出查看范围；
8. 返回 HTML 的可点击绝对路径，并简述证据缺口。
